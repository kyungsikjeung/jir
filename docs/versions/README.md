# 버전/릴리스 정책

이 디렉터리는 파일럿 ASPICE ALM의 버전 관리 규칙을 정의한다.
원칙 10(ASPICE Becomes Sustainable)의 "반복 가능한 릴리스 기반"을 담당한다.

## 1. 단계(Stage)

| 단계 | 브랜치/태그 | 버전 형태 | 의미 |
|---|---|---|---|
| dev | `main` HEAD | `0.x.y-dev` | 개발 중. CI(백엔드 테스트+빌드, 프론트 빌드) 통과가 최소 조건 |
| pilot | `v0.1.0` 이상 (태그 예정) | `0.MINOR.PATCH` | 사내 파일럿 배포. 골든 패스 + 증적 무결성 검증 완료 |
| release | `v1.0.0` 이상 | `MAJOR.MINOR.PATCH` | 외부 이해관계자/공급사 포함 정식 릴리스 |

## 2. SemVer 규칙

- **MAJOR**: 데이터 모델/API 호환이 깨지는 변경 (예: 기준선 잠금 정책 변경)
- **MINOR**: 하위 호환 기능 추가 (예: 자동화 엔진, 새 화면)
- **PATCH**: 버그 수정·문서·테스트·보안 패치 (예: 서명 HMAC 보완)

파일럿 단계에서는 `0.MINOR.PATCH`를 사용하며, MINOR가 마일스톤 완료를 의미한다.

## 3. 태그 규칙

```
v0.1.0   # M1~M4 완료 + 전자서명 무결성 보완 (RELEASE.md 통과 후 부여 예정, 현재 미태깅)
v0.2.0   # 영향 분석 API + ChangeRequest 워크플로우 완료 시
v1.0.0   # 외부 포털/SSO/E2E 완료, 정식 릴리스 시
```

태그는 `RELEASE.md`의 체크리스트를 모두 통과한 커밋에만 붙인다.

## 4. CHANGELOG

변경 이력은 저장소 루트의 [`CHANGELOG.md`](../../CHANGELOG.md)에
"추가 / 변경 / 수정 / 보안" 항목으로 기록한다.
커밋 메시지에 `M{번호} T{번호}:`를 붙여 계획 문서와 추적 가능하게 한다.

## 5. 문서 버전 관리

- 마일스톤 계획: `docs/superpowers/plans/` (변경 금지, 완료 후 보존)
- 검토/분석 문서: `docs/pilot/` (상태 변경 시 날짜를 헤더에 명시)
- 배포/실행 문서: 루트 `README.md`, `DEPLOYMENT.md`, `RELEASE.md`
